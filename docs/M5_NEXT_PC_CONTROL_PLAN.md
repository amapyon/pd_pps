# 次工程：正式M5 PC制御・データ取得の統合計画

更新日：2026-11-12

## 目的

実験24で検証したUSB CDC自動復旧を土台に、PCからPD/PPS Explorerの**能力取得・状態取得・計測・安全な出力設定**を段階的に実装する。ロードマップの正式M5であり、実験内部のM8Fとは番号体系が異なる。

## 守る設計条件

1. **現試作基板のUSB端子は同時使用しない**：CoreBoard J1と追加PC用USB-CはD+/D−を共有する。両方を同時に接続する実機試験は禁止。PD通信とPC USB CDCを同時に評価する前に、PC通信線、USB-C CC・VBUS、電源分離、逆流対策、デバッグ端子の回路を見直し、安全な試験治具を作る。
2. PD/PPSの**要求電流は測定電流でも独立した定電流保護でもない**。電圧・要求電流・実測電流をAPIで明確に区別する。
3. USB再接続で安全な状態を取得し直す。`MEASURE`などの冪等要求は再試行可能だが、出力設定コマンドは**送信成功の不明確さ**を考慮し、無条件に再送しない。
4. 測定の欠測とエラーはログに残し、連続計測を装わない。
5. INA226の精度・校正と、製品用のハードウェア保護は別の受け入れゲートとする。

## 推奨する進め方

| 段階 | 作業 | 通過条件 |
| --- | --- | --- |
| M5-1 読取API定義 | `INFO`、`HEALTH`、`GET_CAPS`、`STATUS`、`MEASURE`の応答形式・エラーと互換性を定義 | ホスト側模擬データで入力境界・エラー・再接続の自動テストPASS |
| M5-2 PD情報の読取結合 | PD17のSource Caps／契約情報をUSB CDC用データ構造へ渡す。まず実機PD同時接続を伴わないホストテストで検証 | 既存PD17制御を変更せず、PDO/APDO・契約状態を矛盾なく返せる |
| M5-3 ハードウェア安全ゲート | PC用USBとPD用USBの独立性、VBUS／GND／電源経路、保護、USB D+/D−の配線を確定 | 安全レビュー・配線資料更新・実測確認の完了 |
| M5-4 実機統合・復旧 | 安全ゲート通過後にPD/PPSとUSB CDCを同時動作。通信断、バスRESET、再接続を検証 | 出力状態を変えずにPC通信復帰。欠測・エラーを適切に記録 |
| M5-5 出力設定API | 明示的な操作権、安全範囲、要求ID、結果照会・再同期を持つPPS設定API | USB断時の二重実行・誤設定を防ぎ、UI競合と保護が成立 |

## 次の着手点

**M5-1：読取専用APIとホストテスト**を次の独立実験として作る。実際のPDO/APDOデータはPD17の記録済みログを入力とし、現段階でPD電源とPC用USBを同時接続しない。既存の実験17（PD17）、21～24と共有ch32funは変更せず、差分を独立した実験フォルダーに収める。

この計画は仕様案であり、M5の製品API実装・実機統合完了を意味しない。
