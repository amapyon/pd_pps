# M2 試験計画：SSD1306 128×64表示とINA226とのI²C共存

- プロジェクト：PD/PPS Explorer
- 作成日：2026-11-02
- ステータス：**M2統合ソース作成・ホストテスト9種類合格／CH32X035実機未ビルド・未検証**
- 基準ファーム：`11_pps_ina226_monitor`（既存実装を改変せず保存）
- 実験フォルダー：`13_oled_ssd1306`（既存ファームへの統合済みソース）
- M2ゲート：**SSD1306で128×64表示でき、INA226（0x40）と同一PA2/PA3ソフトウェアI²C上で安定して通信できること**。
- M1からの繰越：電流・電力の絶対精度と校正は未確定。M2では校正係数を変更しない。

## 1. 検証の範囲

**含む**：OLEDモジュールの電気仕様確認、I²Cアドレス確認、文字・テスト画面表示、INA226共存、表示更新、既存PD/シリアル操作への影響評価。

**含まない**：EC11入力、スタンドアロンのPPS設定UI（M3/M4）、USB PC制御（M5）、電流精度校正（製品基板実装後の評価工程）、短絡・過負荷試験（M7）。

## 2. 準備物と前提

| 品目 | 要件・確認事項 |
| --- | --- |
| WeAct CH32X035 CoreBoard | 既存回路、WCH-LinkE、既存VS Code環境 |
| INA226 R010 | 7-bitアドレス`0x40`、既存VBS→IN−の配線を保持 |
| SSD1306 OLED | 128×64、**I²C 4端子**。SSD1306実装と動作電圧は現物で確認（SH1106等は別実装） |
| 電源 | OLEDを**モジュール仕様で許可された3.3V**から供給。PPS VBUS（5～11V）を接続しない |
| SDA/SCL | 既存ソフトウェアI²C PA3=SDA、PA2=SCL。ライン解放方式は変更しない |
| GND | INA226、OLED、WeActのGND共通。負荷GNDの接続と混同しない |
| プルアップ | OLED基板とINA226基板の抵抗を確認。**SDA/SCLが5Vへプルアップされないこと**を確認 |
| ソフトウェア | 既存のPD・INA226・シリアルコマンド処理を保全。OLEDコードのみ別モジュール追加 |

### 参考配線（OLED部のみ）

```text
CH32X035 3.3V ───── OLED VCC（3.3V対応を現物確認してから）
CH32X035 GND ────── OLED GND
CH32X035 PA2 ────── OLED SCL ───── INA226 SCL（既存）
CH32X035 PA3 ────── OLED SDA ───── INA226 SDA（既存）
                        │                 │
                      (3.3Vへのプルアップ；合成抵抗は現物確認)
```

> モジュール端子の並びは製品により異なる。**ラベルを見て接続**し、4本が同じ順番であると仮定しない。すべて電源OFFで配線変更。供給電圧が不明なら通電しない。

## 3. プログラム設計

1. `m2_ssd1306.c/.h`：SSD1306 I²C初期化、5×7 ASCIIフォント、1024バイトの画面バッファ、**16バイト単位の分割送信**。OLEDアドレス`0x3C`→`0x3D`を試す。
2. `m2_bus_adapter.c/.h`：既存のソフトウェアI²C START／1バイト送信（ACK）／STOPへ**関数ポインターで接続**する。既存GPIOの入出力切替・タイミングは変更しない。
3. `m2_dashboard.c/.h`：画面描画と1秒周期更新。要求PPS電流（REQ）と実測負荷電流（LOAD）を区別する。
4. INA226 BUS=`bus_raw×1.25mV`、電流=`shunt_raw×0.25mA`（R010=10mΩ）、電力=`BUS×電流`はM1と同じ変換を使う。値の更新元は**既存の測定関数**とする。
5. OLEDへの全1024バイト一括送信は避け、メインループ末尾で1回に最大1トランザクションを送る。1回のデータトランザクションは制御バイトを含め17バイト。PDの応答遅延がないことを実機で確認する。

### 表示案（8行、ASCII）

```text
PD/PPS EXPLORER
PPS 9.00V
REQ 1000MA (PD)
BUS 8.85V
LOAD 34.00MA
PWR 0.301W
PD READY INA OK
REQ != LOAD CURR
```

`REQ`は充電器への要求値であり、実測電流や独立した電流制限値ではない。
