# M34 USBFS phase trace / PD connection diagnostic

M33の修正版（-Os -flto）をそのまま引き継ぎ、追加の読み取り専用スナップショットを記録する実験です。PD/PPS制御、USBFS設定、再接続処理は変更していません。M33のTDIAGも残しています。

## 診断設計

USBFS IRQで IN/OUT/SETUP/BUS RESET/SUSPEND フラグを独立に計数し、メインループで累積値をスナップショットに保存します。スナップショットは起動直後(B)、PD初回接続(A)、接続後1/3/5秒(1,3,5)、PD切断検知(D)、切断後500/1500ms(H,J)です。最大8件、最初のPD接続セッションだけ記録します。データはRAM上のみ保持し、再起動で失われます。

**重要**: 切断の検知時刻はphy_attached()に基づくため、物理的な抜去から切断検知までのUSBイベントはPD接続期間に入る可能性があります。USB IRQの状態フラグを計数するもので、転送成功やホスト送信の有無を保証しません。同時に複数のフラグが立った場合はそれぞれを数えますが、同時フラグが独立イベントを意味するとは限りません。

## コマンド

- `WDIAG`: サンプル数と接続検出有無
- `WDIAG S0` ～ `WDIAG S7`: サンプルの位相（B/A/1/3/5/D/H/J）、時刻(ms)、PD接続状態、Policy Engine状態、USB Configuration、UDEV_CTRL
- `WDIAG C0` ～ `WDIAG C7`: そのサンプル時点でのUSBイベント累積回数

PD充電器を取り外しUSB CDCが復帰した後、`Read-M34-Diag.ps1 -Port COM10` を実行してください。値の**差分**が各期間のイベント回数です。PD接続は5秒以上保持することを推奨します（PPSの契約・温度・電源異常があれば直ちに中止）。

## 使用手順

1. `Test-M34-Host.ps1` を実行し、次に `Build-M34.ps1` を実行。Windowsでターゲットのビルドを検証してください。
2. M33のバイナリを保管し、PDとPC USBを外して前回成功したWCH-LinkE環境で書き込んでください。
3. PD未接続でLED点滅・USB CDC動作を確認し、PD接続で現象が再現されるか観察します。
4. PD切断後、できれば2秒以上待ってCOM復帰後に診断を読み出します。

静的テストPASSはターゲットビルドまたは実機正常動作を保証しません。
